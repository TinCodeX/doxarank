# 4.9.3 — Agent Reliability & Failure Recovery

Audit the current agent runtime and implement missing reliability controls.

Handle at minimum:

### LLM failure

* timeout
* malformed response
* unavailable provider
* invalid tool call

### Tool failure

* timeout
* malformed result
* unexpected exception
* unavailable tool

### MCP failure

* server unavailable
* tool unavailable
* malformed schema
* malformed result
* authorization failure
* timeout

### External API failure

Examples:

* GSC
* SERP
* CMS
* crawler
* analytics provider

### Agent behavior failure

Handle:

* repeated tool calls
* excessive iterations
* invalid tool arguments
* impossible plans
* contradictory observations
* empty evidence
* failed verification

Introduce bounded controls where missing:

* max agent iterations
* execution timeouts
* retry policies
* exponential backoff where appropriate
* failure classification
* safe termination
* partial-result handling
* idempotency for executable actions
* correlation IDs
* structured error results

Do NOT silently retry dangerous mutations.

# 4.9.5 — Agent Evaluation Foundation

Introduce a small but extensible Agent Evaluation layer.

Do NOT build a huge evaluation platform.

The purpose is to establish the foundation for Milestone 5.

Create a structure capable of evaluating an AgentRun using dimensions such as:

```text
Task Success
Tool Selection
Evidence Quality
Reasoning Progress
Safety Compliance
Action Correctness
Verification Success
Outcome Quality
Efficiency
```

A possible model/service structure is:

`SEOAgentEvaluationService`

and, if appropriate after inspecting the architecture:

`AgentEvaluation`

Store enough information to evaluate an agent trajectory without storing secrets.

At minimum calculate:

* success/failure
* number of steps
* number of tool calls
* failed tool calls
* execution duration
* approval required
* approval result
* action execution result
* verification result
* outcome result

Do not attempt to automatically judge hidden chain-of-thought.

Evaluate observable behavior, tool trajectories, evidence, outputs, safety and outcomes.

Add a tool or API only if it naturally fits the existing architecture.
