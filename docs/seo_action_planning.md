# DoxaRank — Autonomous SEO Action Planning, Execution & Empirical Verification (Milestone 4, Phase 4.4)

## 1. Architectural Overview

DoxaRank Milestone 4 Phase 4.4 completes the closed-loop autonomous SEO lifecycle:

```text
┌──────────────┐     ┌────────────────┐     ┌────────────────────┐     ┌──────────────────────┐

                                                                                  │
                                                                                  ▼
┌──────────────┐     ┌────────────────┐     ┌────────────────────┐     ┌──────────────────────┐
```

## 2. Key Pillars

### 2.1 Plannable vs. Executable Action Separation
- **Plannable Actions**: Any diagnostic, ranking drop investigation, content enhancement, or technical fix proposal generated by the planner.
- **Executable Actions**: Actions with a supported mutation connector (`update_title`, `update_meta_description`, `update_canonical`, `add_redirect`, `publish_content_draft`).
- Non-executable actions generate structured advisory tasks and Jira/GitHub exportable tickets without throwing mutation errors.

### 2.2 Deterministic Risk Classification
Every action is assigned an independent deterministic risk level:
- **`LOW`**: Meta descriptions, image alt tags, performance investigations.
- **`MEDIUM`**: On-page H1 updates, internal linking, content optimizations.
- **`HIGH`**: Title tags, canonical URL alterations, URL slug changes.
- **`CRITICAL`**: Removing redirect chains, sitewide schema changes, bulk URL modifications.

Aggregate plan risk is calculated deterministically as $\max(\text{child action risk levels})$.

### 2.3 Empirical Real-World Verification
> **Execution Success $\neq$ SEO Success**

The `SEOActionVerifier` service probes the target URL over HTTP/HTTPS and inspects the live DOM/headers:
1. Validates HTTP response status code (e.g. `200 OK`).
2. Parses the live HTML document using BeautifulSoup / regex.
3. Compares expected metadata (`<title>`, `<meta name="description">`, `<h1>`, `<link rel="canonical">`, `<img>` alt tags) against observed values.
4. Generates an evidence payload with before-and-after state comparison, diff, and verification status (`VERIFIED` or `FAILED`).

### 2.4 Strict Multi-Tenant Security & Concurrency
- Project ownership isolation enforced at view, serializer, service, and task levels (`project.owner == request.user`).
- Database row-level locking (`select_for_update`) during plan state transitions (approval, rejection, execution, verification).

## 3. Database Schema

### `SEOActionPlan`
- **`project`**: `ForeignKey(Project, on_delete=CASCADE, related_name='action_plans')`
- **`title`**: `CharField(max_length=255)`
- **`summary`**: `TextField(blank=True)`
- **`status`**: `CharField(choices=ActionPlanStatus.choices, default=PROPOSED)`
  - `proposed`, `under_review`, `approved`, `rejected`, `executing`, `completed`, `partially_completed`, `failed`, `cancelled`
- **`risk_level`**: `CharField(choices=ActionRiskLevel.choices, default=LOW)`
- **`confidence_score`**: `FloatField(default=0.0)`
- **`requires_human_approval`**: `BooleanField(default=True)`
- **`approved_by`**: `ForeignKey(User, null=True, blank=True)`
- **`approved_at`**: `DateTimeField(null=True, blank=True)`
- **`rejection_reason`**: `TextField(blank=True)`
- **`verification_status`**: `CharField(choices=VerificationStatus.choices, default=UNVERIFIED)`
- **`verification_results`**: `JSONField(default=dict, blank=True)`
- **`provenance`**: `JSONField(default=dict, blank=True)`

### `SEOAction` Extensions
- **`plan`**: `ForeignKey(SEOActionPlan, null=True, blank=True, related_name='actions')`
- **`verification_status`**: `CharField(choices=VerificationStatus.choices, default=UNVERIFIED)`
- **`verification_result`**: `JSONField(default=dict, blank=True)`

## 4. API Reference

| Method | Endpoint | Description |
|---|---|---|
| `POST` | `/api/seo/ai/action-plans/plan/` | Generate a new structured `SEOActionPlan` from project audits and GSC metrics. |
| `GET` | `/api/seo/ai/action-plans/` | List action plans for the current project. |
| `GET` | `/api/seo/ai/action-plans/{id}/` | Retrieve full plan details including child actions and verification results. |
| `POST` | `/api/seo/ai/action-plans/{id}/approve/` | Approve the plan and all linked child actions. |
| `POST` | `/api/seo/ai/action-plans/{id}/reject/` | Reject the plan with an audit reason. |
| `POST` | `/api/seo/ai/action-plans/{id}/execute/` | Execute all approved child actions asynchronously via Celery. |
| `POST` | `/api/seo/ai/action-plans/{id}/verify/` | Run real-world verification on all executed actions. |
| `POST` | `/api/seo/ai/actions/{id}/verify/` | Run empirical real-world verification on an individual action. |

---

## 5. ToolRegistry Integration

The following tools are registered and available to AI agents:
1. **`plan_seo_actions`**: Synthesizes project audit defects and GSC momentum drops into a structured `SEOActionPlan`.
2. **`get_action_plan`**: Fetches plan details, child actions, aggregate risk, and verification status.
3. **`verify_seo_action`**: Empirically inspects live target HTML for an individual action.
4. **`verify_action_plan`**: Empirically verifies all actions in an `SEOActionPlan`.
